## Dev Container

### Docker won't start

**Symptoms**: Docker Desktop fails to launch or reports an error on startup.

**Fixes**:

1. **Windows**: Ensure WSL 2 is enabled (`wsl --install` or `wsl --update`). Restart Docker Desktop after enabling WSL 2.
2. **Mac**: Check that virtualization is enabled in System Settings.
3. Restart Docker Desktop. If it still fails, try resetting to factory defaults.

### Container fails to build

**Symptoms**: "Build failed" or timeout when reopening in container.

**Fixes**:

1. Ensure Docker Desktop is running and has at least 4 GB of RAM allocated. Check the build log and access to `mcr.microsoft.com` and your approved package feeds.
2. Microsoft employees should fully close VS Code and use the host launcher before opening the container. Other organizations should configure their approved feeds on the host. See [Setup Guide: create your repository](../../getting-started/setup/#setup-steps).
3. If build-time feed settings changed, relaunch with those settings and run `Dev Containers: Rebuild Container`. Wait for post-create setup and check the package-source labels in the startup output.
4. If the build still fails, preserve the error and ask your organization or facilitator. Do not disable TLS checks, bypass execution policy, or switch to unapproved public feeds.

The participant container uses digest-pinned Azure Linux 4 preview. Ubuntu in WSL is the host, not the container. Codespaces requires separate event validation.

### Extensions not loading

**Symptoms**: Copilot Chat or Bicep extension missing after container starts.

**Fix**: The recommended extensions are in `.vscode/extensions.json`.
Run `Extensions: Show Recommended Extensions` and install any that are missing.

## Azure CLI

### `az login` fails inside Dev Container

**Symptoms**: Browser-based login does not redirect back.

**Fix**: Use device code flow:

```bash
az login --use-device-code
```

### Subscription not found

**Symptoms**: Deployment fails with "subscription not found".

**Fixes**:

1. List available subscriptions: `az account list --output table`
2. Set the correct one: `az account set --subscription "<name-or-id>"`

## Bicep

### `bicep build` fails with module errors

**Symptoms**: "Unable to restore module" or "module not found".

**Fixes**:

1. Clear the Bicep module cache: `bicep restore <file>`
2. Ensure you have internet access (AVM modules are fetched from `mcr.microsoft.com`)
3. Check the module version exists: `bicep publish` errors often mean a typo in the version

### Lint warnings about parameter descriptions

**Symptoms**: `no-unused-params` or `missing-description` warnings.

**Fix**: Every `param` must include a `@description()` decorator. Example:

```bicep
@description('The Azure region for all resources.')
param location string = resourceGroup().location
```

## Copilot Agents

### Copilot not working

**Symptoms**: Copilot Chat is unresponsive or shows authentication errors.

**Fixes**:

1. Sign out of GitHub in VS Code and sign back in with the correct account
2. Reload VS Code (`Developer: Reload Window`)
3. Verify your Copilot subscription at [github.com/settings/copilot](https://github.com/settings/copilot)
4. Select the **Copilot** session target and confirm the selected model is allowed by your account and organization

### Selected model is not available

**Symptoms**: A Copilot session or Accelerator agent cannot start with the selected model.

**Fixes**:

1. Confirm the session uses the **Copilot** harness; choosing a model does not select the harness.
2. Check your Copilot plan entitlements, the selected model, and organization model policy.
3. Ask the GitHub organization or enterprise owner to resolve blocked access, or select a permitted model.
4. Reload VS Code after any policy changes and retry the bounded capability check.

Current Accelerator agent definitions do not pin a model. Do not edit an agent file or invent a model pin to hide an access failure.

### Agent not appearing in Chat

**Symptoms**: An interactive agent such as `01-Orchestrator` does not appear in the agent picker.

**Fixes**:

1. Confirm that you opened the template-derived repository, not this documentation repository.
2. Confirm the repository is open in its Dev Container.
3. Verify the expected files exist under `.github/agents/`.
4. Reload VS Code with `Developer: Reload Window`.
5. Compare the repository with the current APEX Accelerator if files are missing.

Do not enable a legacy discovery setting as a substitute for loading the current repository configuration.

### Agent produces incomplete output

**Symptoms**: Agent stops mid-response or skips steps.

**Fixes**:

1. Break large requests into smaller steps
2. Provide explicit file paths when referencing artifacts
3. Preserve the actual task error and ask `01-Orchestrator` to continue the remaining authorized work, or use the recovery steps below
4. Review the resulting artifacts and recorded findings; an incomplete response is not a completed review or stage approval

### Native task or independent review fails

**Symptoms**: An owner cannot be dispatched, a reviewer fails, or findings are missing even though the agent appeared in Chat.

**Fixes**:

1. Check the **Copilot** session target, selected model policy, correct Accelerator repository, and availability of the declared native agent and task tools. Run the configuration checks in [setup step 9](../../getting-started/setup/#setup-steps). Retry only when the workflow permits and within the existing attempt budget.
2. If a delegated owner returns `REVIEW_REQUIRED` because it cannot launch a nested task, the Orchestrator can invoke the same `challenger-review-subagent` as an independent sibling and return the actual recorded result to the owner.
3. If a reviewer ran but its receipt is missing, preserve the real task result and recording error. Ask the owner or facilitator to investigate the existing review recorder and provenance checks; do not call it an unavailable reviewer merely to start a new review.
4. If the parent reviewer, tool, or model is genuinely unavailable, stop the affected stage and escalate. Do not fabricate findings, reset review attempts, self-review, or use the optional `10-Challenger` wrapper to hide a failed automatic review.

### MCP servers not working

**Symptoms**: A GitHub or Azure MCP server declared by the Accelerator returns an error or is unavailable.

**Fixes**:

1. Inspect root `.mcp.json` in the template-derived repository and identify the failing `github` or `azure-mcp` server. The portable configuration uses a top-level `mcpServers` object.
2. Preserve the exact startup or authentication error.
3. Confirm account and organization policy permits the declared server.
4. For Azure-backed tools, confirm Azure sign-in and subscription context where required. For startup failures, check access to the approved package feed.
5. Reload VS Code with `Developer: Reload Window`.
6. Compare your MCP configuration with the [reviewed Accelerator configuration](https://github.com/jonathan-vella/apex-accelerator/blob/9e7432ca90a9db86e9f85f28d3afd6db78d97c19/.mcp.json). Do not add servers that have not been reviewed as a workaround.

GitHub reference: [Configure MCP server access](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-mcp-usage/configure-mcp-server-access)

APEX reference: [MCP server integration](https://apexops.pro/concepts/how-it-works/mcp-integration/)

### Pricing evidence is missing or incomplete

**Symptoms**: Architecture has a cost summary but no current complete pricing result, or Azure MCP pricing fails.

1. Preserve the exact startup, tool-discovery, authentication, or pricing error. An unavailable tool does not by itself prove an Azure authentication failure.
2. Check the current registered pricing JSON, initially `02-cost-estimate.json`, for `COMPLETE` status, matching meter identifiers, usage, currency, and source evidence. A valid registered versioned result can also be current.
3. The pricing worker may use its [documented direct Retail Prices API fallback](https://github.com/jonathan-vella/apex-accelerator/blob/9e7432ca90a9db86e9f85f28d3afd6db78d97c19/.github/skills/apex-azure-defaults/references/pricing-guidance.md#constrained-direct-api-fallback) only for eligible MCP failures or ambiguities and must retain labelled evidence and the existing request budget. Otherwise stop and escalate; do not guess prices or invent a successful estimate.
4. Compare the returned currency and usage assumptions with the EUR budget and document any conversion. Retail estimates are not actual spend; historical spend and forecasts use authorized Cost Management REST calls through `az rest`.

### Resume a paused or interrupted workflow

**Symptoms**: A stage was approved and paused, a task was interrupted, or the chat lost context.

In Copilot Chat, use the project's resume command:

```text
/apex-workflow-start resume freshconnect
```

For read-only inspection inside the participant container, run:

```bash
apex-recall handoff freshconnect --json
apex-recall show freshconnect --json
```

The recovery summary `00-handoff.md` helps identify the current owner and evidence; it is not an approval. Preserve existing findings, attempts, and approvals. Do not hand-edit `00-session-state.json`, reinitialize the project, or reset review history to force progress. A resumed or replacement task still needs its original scope and any separate human authorization.

New projects use `practical-v1`; older projects do not adopt it automatically. Follow the [workflow adoption guidance](https://github.com/jonathan-vella/apex-accelerator/blob/9e7432ca90a9db86e9f85f28d3afd6db78d97c19/.github/skills/apex-workflow-engine/references/practical-workflow.md) for any owner-approved migration.

## Validation and Linting

Run the commands in this section from the root of your working repository created
from the accelerator template, not from this documentation repo.

### `npm run lint:md` fails

**Symptoms**: markdownlint reports errors.

**Fix**: Auto-fix most issues:

```bash
npm run lint:md:fix
```

For remaining issues, check `.markdownlint-cli2.jsonc` for the rule that fired.

### `npm run lint:links` reports broken links

**Symptoms**: `markdown-link-check` finds dead links.

**Fixes**:

1. For internal links: verify the target file exists
2. For external links: check if the URL is behind authentication or geo-blocked
3. Add false positives to `.markdown-link-check.json` ignore patterns

## Secrets and Credential Leakage

### Secret appears in agent output or committed file

**Symptoms**: A connection string, access key, or password is visible in an agent-generated file or Git history.

**Fixes**:

1. **Rotate the credential immediately** — regenerate the key or password in the Azure portal or CLI
2. Replace the secret with a placeholder (`<your-connection-string>`) in the file
3. If already committed, remove from Git history or notify your facilitator
4. Use Key Vault references or environment variables going forward

### Preventing secret leakage

- Never paste real secrets into Copilot Chat prompts
- Review all agent-generated files before committing
- Use `az keyvault secret set` to store secrets safely
- Use managed identities where possible to avoid secrets entirely

## Policy Errors and Governance

### `RequestDisallowedByPolicy` on deployment

**Symptoms**: Deployment fails with a policy violation error naming a specific policy.

**Diagnosis**:

1. Read the error message — it names the policy that denied the operation
2. Common MicroHack policies: required tags (`Environment`, `Project`), HTTPS-only, TLS 1.2, allowed locations

**Fixes by policy type**:

| Policy denial                          | Fix                                                    |
| -------------------------------------- | ------------------------------------------------------ |
| Missing `Environment` or `Project` tag | Add `tags` block to every resource in your Bicep       |
| Storage not HTTPS-only                 | Set `supportsHttpsTrafficOnly: true`                   |
| Storage TLS version                    | Set `minimumTlsVersion: 'TLS1_2'`                      |
| Storage public blob access             | Set `allowBlobPublicAccess: false`                     |
| SQL not Microsoft Entra ID-only        | Set `azureADOnlyAuthentication: true`                  |
| App Service not HTTPS                  | Set `httpsOnly: true`                                  |
| Location not allowed                   | Deploy to `swedencentral` or `germanywestcentral` only |

### Policies not taking effect

**Symptoms**: Deployment succeeds but you expected a policy denial, or `Get-GovernanceStatus.ps1` shows `Unknown`.

**Fixes**:

1. Azure Policies take 5–15 minutes to propagate after deployment
2. Ask your facilitator to run `pwsh -File scripts/Get-GovernanceStatus.ps1 -Subscription "<subscription-name-or-id>" -MicrohackOnly` to check activation status
3. If status is `Unknown`, wait 10 minutes and re-check
4. If still not active after 30 minutes, ask facilitator to re-run `Setup-GovernancePolicies.ps1`

:::tip

Even if policies haven't propagated yet, add the required tags and security settings to your Bicep — they are part of the success criteria.

:::

### Escalation

If you cannot resolve a policy error after checking the table above, ask your facilitator. Provide the full error message and the resource type you were deploying.

## Quota Errors

### `QuotaExceeded` on deployment

**Symptoms**: Deployment fails with quota or capacity error for a specific resource type or region.

**Fixes**:

1. Check current usage: `az vm list-usage -l swedencentral -o table`
2. Try a smaller SKU (e.g., S1 instead of P1v3)
3. Try the secondary region (`germanywestcentral`)
4. Delete unused resources from previous attempts
5. Ask your facilitator for help if no quota is available

## Deployment Errors

### `NameNotAvailable` or `StorageAccountAlreadyTaken`

**Symptoms**: Globally unique resource name is already in use.

**Fix**: Use `uniqueString(resourceGroup().id)` suffix pattern in your Bicep naming convention.

### `AuthorizationFailed` during deployment

**Symptoms**: Deployment fails with permission error.

**Fixes**:

1. Verify you're targeting the correct subscription: `az account show`
2. Re-authenticate: `az login --use-device-code`
3. Confirm you have Owner or Contributor role on the subscription

### Deployment timeout or partial failure

**Symptoms**: Some resources create successfully, others fail or time out.

**Fixes**:

1. Check the deployment status in the Azure portal (Resource group → Deployments)
2. Look for the specific resource that failed and its error message
3. Preserve the exact error and escalate to the facilitator or the selected
   `07b-Bicep Deploy` or `07t-Terraform Deploy` agent. Participants must not
   substitute direct Azure CLI deployment for the approved agent path.

## MicroHack-Specific

### Governance policies not applying

**Symptoms**: `Setup-GovernancePolicies.ps1` runs but policies don't appear.

**Fix**: Policy assignments can take up to 30 minutes to propagate.
Ask your facilitator to verify policy status with:

```powershell
pwsh -File scripts/Get-GovernanceStatus.ps1 -Subscription "<subscription-name-or-id>" -MicrohackOnly
```
